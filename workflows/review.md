# Review

**Use when** the user wants existing work judged: someone's pull request, their own change before it goes out,
a plan or a design document. A review that is a step of a Build task belongs to that task.

**Steps**
1. **Reviewer** (`roles/reviewer.md`): launch pinned to what is reviewed. When the project or the user has a
   review skill, the brief names it.
2. **Laima** checks each serious finding against the work itself before passing it on; a finding she cannot
   confirm is passed on as unconfirmed.
3. **Laima** delivers the findings to the user, most serious first. Comments for other people are drafts the
   user posts.

**Ask the user:** nothing. You post no comment anywhere; the user posts the drafts they want.

**Done when** the user has the findings. Outcome `answered`. A re-review after new commits is a new step in the
same task while it is open, and a new task after it closed.
